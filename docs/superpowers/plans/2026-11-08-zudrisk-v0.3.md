# ZudRisk v0.3 (snow quality: ERA5-Land) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Score snow from ERA5-Land instead of GLDAS, as the spec decided ahead of time for latency reasons. Add two display-only snow layers, snow-cover days and a dense-snow (ice-crust) proxy, and write up how GLDAS and ERA5-Land compare.

**Architecture:**
- One CDS job fetches ERA5-Land monthly means (snow depth, snow density, snow cover) for every winter month 2001–2024 over Mongolia, as one NetCDF file.
- `era5.py` reduces that file to soum series, the same way `gldas.py` does.
- `indicators.py` takes snow from a single `SNOW_SOURCE` and keeps GLDAS as a comparison column.
- `compare.py` writes the comparison page.

**Tech Stack:** Same as v0.2. No new dependency: the CDS API is plain HTTPS with a `PRIVATE-TOKEN` header, so `cdsapi` is not needed.

**Spec:** `docs/superpowers/specs/2026-11-08-zudrisk-design.md` (§4.3 calls, §5, §7 v0.3 row). Previous plans: v0.1 and v0.2 in this folder. Their Global Constraints still hold.

## Global Constraints

Everything in the v0.1 and v0.2 Global Constraints applies, plus the following.

**Scoring snow source**
- From v0.3 the score uses ERA5-Land `snow_depth`.
- This is fixed by the spec's latency argument, not by which product validates better.
- GLDAS stays as a comparison only. Nothing in `compare.py` may feed back into the score.
- The snow indicator definition is unchanged: winter max of the soum's monthly mean depth in m, z against winters 2001/02 … 2020/21.

**Display-only layers**

These carry no weight and are labelled "unvalidated" on the site.
- `snow_days`: the sum over Nov … Mar of (monthly mean snow cover % / 100 × days in that month).
- `density_kgm3`: the winter max of monthly mean snow density, over months whose mean depth is ≥ 0.01 m. Below that it is None.
- `z_density`: density as a z-score against the 2001/02 … 2020/21 baseline.
- The site quotes Resolution 286's thresholds next to them: white dzud ≥ 250 kg/m³, iron dzud ≥ 350 kg/m³.

**Licence and credentials**
- Licence: ERA5-Land is CC-BY. The site's sources line gains "Contains modified Copernicus Climate Change Service information (2026)".
- Credentials are read only from `~/.cdsapirc` (`url:` and `key:` lines).
- The key is never printed, logged, or written anywhere under the repo.

## Data endpoints (checked live 2026-11-08 with the user's CDS token)

**Config.** `~/.cdsapirc` holds `url: https://cds.climate.copernicus.eu/api` and `key: <36-char UUID>`. Every request sends the header `PRIVATE-TOKEN: <key>`.

**Submit.**
- Send `POST {url}/retrieve/v1/processes/reanalysis-era5-land-monthly-means/execution` with body `{"inputs": {...}}`.
- The reply is `{"status": "accepted", "jobID": ...}`.
- A bad token returns 401 with `{"title": "Authentication failed"}`.
- The licence is already accepted: the probe job ran.

**Inputs:**
  ```json
  {"product_type": ["monthly_averaged_reanalysis"],
   "variable": ["snow_depth", "snow_density", "snow_cover"],
   "year": ["2001", …, "2024"], "month": ["01","02","03","11","12"], "time": ["00:00"],
   "area": [52.2, 87.0, 41.5, 120.0], "data_format": "netcdf", "download_format": "unarchived"}
  ```

**Poll.**
- `GET {url}/retrieve/v1/jobs/{jobID}` until `status` is `successful`.
- A status of `failed` or `rejected` raises.
- Single-month probes queued for 1 s, 43 s and 390 s. Poll every 15 s for up to 60 min.

**Result.** `GET {url}/retrieve/v1/jobs/{jobID}/results` returns `asset.value.href`. That is a public object-store URL on `object-store.os-api.cci2.ecmwf.int`, fetched without the token.

**File.** NetCDF4 with these variables:

| Variable | Shape or unit |
|---|---|
| `valid_time` | seconds since 1970-01-01 |
| `latitude` | 108 values, 52.2 → 41.5 |
| `longitude` | 331 values, 87.0 → 120.0 |
| `sde` | m |
| `rsn` | kg m⁻³ |
| `snowc` | % |

- Probe for Jan 2024: sde mean 0.177 m, rsn mean 152 and max 239 kg m⁻³, snowc mean 72.8 %. No masked cells.
- Expected size for 120 months × 3 variables is about 40–60 MB.
- Cached at `data/raw/era5_land_monthly.nc` (gitignored).

## File structure

```
pipeline/http.py          + cds_retrieve(dataset, inputs, opener=None) -> bytes: submit, poll, fetch; 401/403 -> RuntimeError naming ~/.cdsapirc
pipeline/era5.py          one cached job -> data/derived/soum_era5.csv (pcode, yyyymm, sde_m, rsn_kgm3, snowc_pct)
pipeline/indicators.py    SNOW_SOURCE = "era5"; + snow_days(), density(); columns + z_snow_gldas, snow_days, density_kgm3, z_density
pipeline/compare.py       GLDAS vs ERA5-Land per winter -> data/derived/snow_comparison.json + docs/research/snow-comparison.md
pipeline/hindcast.py      runs compare after the winters
pipeline/export.py        + new props
site/app.js, index.html   popup: snow days, density with the 286 thresholds, "unvalidated"; sources + C3S line; limits: snow = ERA5-Land
```

Existing callers stay compatible:
- `validate.main` reads `z_<k>` for the four scored keys only.
- `app.js` reads `snow_m` and the `z_*` props by name.
- All existing columns keep their names. Only new ones are added.

## Review Focus

1. **A CDS job that fails or is rejected** raises with the job id and the server's message, and is never cached as data. Covered by an `http` check with a fake opener.
2. **A wrongly pasted token** (the user's first paste was 91 chars of other text) gives a 401 error that names `~/.cdsapirc` and says the key is the profile's API Token. Covered by an `http` check.
3. **Density in a snow-free month** (Gobi winters with almost no snow): ERA5 carries a nominal density even on bare ground, so no density is taken where depth < 0.01 m. Covered by an `indicators` check.
4. **`valid_time` decoding**: seconds since 1970 become `yyyymm` with no timezone drift at a month boundary. Covered by an `era5` check.
5. **The comparison must not change the score**: the risk column is identical before and after `compare.main()`. Covered by a run-order check in Task 4.

## Rulings recorded in this plan (deviations from the spec's v0.3 row)

**The ice-crust proxy uses monthly density, not a daily thaw-refreeze count.**
- What changed: ERA5-Land monthly mean snow **density**, judged against Resolution 286's own density thresholds, replaces the daily thaw-refreeze proxy.
- Why: the daily-statistics dataset was still queued after 9 minutes for two days in the probe, while monthly density takes one fast job.
- Cost: a monthly mean damps short crust events. The Jan 2024 maximum was 239, so the 350 line may never be reached. The site therefore shows the value and its z, not a yes/no flag.

**Snow-cover days use the ERA5-Land model, not MODIS MOD10CM observations.**
- What changed: snow-cover days come from ERA5-Land `snow_cover`.
- Why: MOD10CM is not on OPeNDAP (404, checked), and its HDF4 files would need a new dependency (`pyhdf` or GDAL).
- Cost: a model field stands in for an observation, on a display-only layer.

## Not in v0.3

- MODIS observed snow cover. It needs an HDF4 reader; ask before adding one.
- VIIRS continuity and the 2026/27 outlook. These are v0.4.
- Deferred v0.2 minors: lake NDVI pixels, the duplicate mortality code in `hindcast`, and the CMR sort key.
